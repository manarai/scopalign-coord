# O2 — Operator-estimated alignment on real technical batches (run-to-run, chemistry)

status: pre-registered (written 2026-10-15 before any O1-series result; issue after an O1-series task selects an estimator)
blocked_by: O1-series selection (PROJECT.md rule 14)
seed: 20261014
planner_commit: 033378b
kind: planned (operator-central alignment, PROJECT.md rule 13)

## Purpose

Apply the operator-only rotation estimator selected in the O1 series to two
real, purely technical batches from one donor, **estimate `Q` from operators
and drift only, apply it to the latent space (`z_A ↦ Q z_A`)**, and judge the
alignment by operator agreement, mixing and preservation of cell types,
with before/after views.

1. **run** — run-to-run, same chemistry: K1's matched pair (A = 1k v3,
   B = 10k v3 subsample; 1113 cells each).
2. **chem** — chemistry: K2's matched pair (A = v2, B = v3 thinned to v2's
   depth; 969 cells each).

## Scope

### In scope
- **Estimator:** the one named by the O1-series review (`selected_estimator`
  of O1, or the first of O1b–O1e that works), with **exactly** the
  settings in its task file (drift config, five seeds, matching groups,
  starts, iterations, losses). The planner writes its name into this line
  when issuing: **estimator = `<to be filled at issue>`**, minimum cell count
  `min_n` = `<to be filled>`. Its target-free parts only: no `Q_load`, no
  labels beyond what the estimator itself uses (coarse types for matching
  groups, if any), no positions.
- **Inputs (record sha256 of each):**
  - run: `data/pbmc_10k_v3/A_matched.h5ad`, `data/pbmc_10k_v3/B_matched.h5ad`,
    `reports/T01e/genes.txt`, `reports/K1/latent_pca30_a.npy`,
    `reports/K1/latent_pca30_b.npy`;
  - chem: `data/pbmc_v2_v3/pbmc_v2.h5ad`, `data/pbmc_v2_v3/pbmc_v3_thin.h5ad`,
    `data/pbmc_v2_v3/k2_cells.csv`, `reports/T01d/genes.txt`,
    `reports/K2/latent_pca30_a.npy`, `reports/K2/latent_pca30_b.npy`,
    `reports/T02b/loadings.npz`.
  Latents are used as committed; no new PCA for the separate frames.
- **Reference rotation (comparison only, never used in the estimate):**
  run: re-derive each dataset's PCA as K1 (subset to the 2000 genes, then
  `normalize_total(1e4)`, `log1p`, `PCA(30, svd_solver="full",
  random_state=20261014)`), check scores equal K1's latents
  (`latent_check_max`), `Q_load = U Vᵀ` of `W_B W_Aᵀ`. chem: `Q_load` from
  `reports/T02b/loadings.npz`.
- **Per pair:**
  1. Fit drifts and estimate `Q̂` with the selected estimator.
  2. `q_vs_load = ‖Q̂ − Q_load‖_F / sqrt(60)`.
  3. Operator frame agreement under `Q̂`, T02c's definitions: clusters =
     coarse types with ≥ 100 cells in both; centroid operators
     (`centroid_operator(..., n_cells_centroid=30)`) from the seed-20261014
     fits; `frame_ratio_10` = top-10 residual of `(Q̂ C^A Q̂ᵀ)` vs `C^B` ÷
     T02c's refit null (`default_rng(20261022)`, seed pairs 20261014 vs
     20261016…19); `frame_ratio_30` = the same in full 30-d.
  4. Views and scores (T02c/T05a definitions): `joint` (stack, subset genes
     first, `normalize_total`, `log1p`, one PCA(30)), `noA` (`[z_A ; z_B]`),
     `op` (`[z_A Q̂ᵀ ; z_B]`), `load` (`[z_A Q_loadᵀ ; z_B]`, reference);
     `mix` (30 nearest other cells, ÷ 0.5) and `sil` (tested coarse types)
     on each 30-d embedding; UMAPs with `n_neighbors=15`, `min_dist=0.5`,
     `random_state=20261014`.
- **Order:** run first, then chem.

### Out of scope
- Changing the estimator or any of its settings; using `Q_load`, labels or
  positions to estimate or refine `Q̂`; any local or non-orthogonal map.
- Other pairs or datasets; any biological claim.

### Decision rule (per pair)
0. **Validity:** `symmetry_max > 1e-4` or `latent_check_max > 1e-4` →
   **REVISE**. `n_cells_<p> < min_n` → that pair **stopped** (the estimator
   is not validated at this cell count).
1. **succeeds** if `frame_ratio_10_<p> ≤ 1.5` **and** `mix_op_<p> ≥ 0.80`
   **and** `sil_op_<p> ≥ 0.9 × sil_joint_<p>`.
2. **fails** if `frame_ratio_10_<p> > 3.0` **or** `mix_op_<p> < mix_noA_<p>`.
3. Otherwise **inconclusive**.

**Secondary readings (not the outcome):** `q_vs_load_<p> ≤ 0.25` — the
operators recover the gene-defined frame map; `frame_ratio_30_<p>` beside
`frame_ratio_10_<p>`; `mix_op` vs `mix_load` — operator-estimated vs
gene-loading rotation; chem only: compare with T05a's Harmony
(`mix` 1.001, `sil` 0.447).

### What would change my mind
If the operator-estimated rotation, validated on known answers, fails on a
real same-donor technical batch, then operator fields of real runs differ
in ways the known-answer tests did not capture, and the estimator is not
yet usable for correction.

## Procedure

1. `o2_run.py --stage run` — drifts, `Q̂`, frame agreement, views →
   `run/Q_hat.npy`, `run/centroid_ops.npz`, `run/scores.csv`,
   `run/fig_umap.png` (4 views × coloured by dataset / cell type; titles
   with mix, sil, frame ratio).
2. `o2_run.py --stage chem` — the same under `chem/`.
3. `o2_run.py --stage report` — `report.json`, checksums, lockfile.

`o2_run.py` must accept `--stage all`.
