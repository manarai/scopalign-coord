# T04b — Sweep: when does a rigid correction keep biology that Harmony and scVI remove?

seed: 20261014

motivated_by: reports/T04/REVIEW.md — at one setting the rigid gene-loading rotation removed the batch and kept the interferon response (0.91) while Harmony and scVI kept 0.63; one setting proves nothing general

## Purpose

Map where the rigid correction's advantage holds and where it breaks, on
T04's semi-synthetic design, varying (1) the size of the biological change,
(2) the strength of the batch effect and (3) whether the batch effect is the
same for every cell type or differs by cell type (which no rigid map can
undo). No drift fits, no operators.

## Scope

### In scope
- **Data construction:** exactly T04's (`tasks/T04.md`: K0 halves, A = H1,
  B = H2, `genes.txt`, the 22 interferon genes, the same 947 responders from
  `default_rng(20261100)`, Poisson draws from `default_rng(20261102)`, A
  resampled once), with three parameters:
  - **Biology size `f` ∈ (0, 1, 2, 4, 8):** responder increment
    `Poisson(f · (μ_g + 0.1) · n_c / n̄)`. `f = 0` is the no-biology control
    (responders tracked as pseudo-responders). T04's S1 is `f = 4`.
  - **Batch strength `σ` ∈ (0.25, 0.5, 1.0):** `b_g = exp(σ · ε_g)`, with the
    same standard normals `ε_g` for every condition
    (`default_rng(20261101)`, genes in `genes.txt` order); depth factor 0.7
    always. T04 used `σ = 0.5`.
  - **Batch type ∈ (`global`, `celltype`):** `global` = T04's. `celltype`
    adds, for B only, a per-(coarse type, gene) factor `exp(0.3 · η_tg)`
    (`default_rng(20261103)`, types sorted, genes in order) multiplied into
    `b_g`.
  - 5 × 3 × 2 = **30 conditions**. Oracle per (`f`, batch type): B with
    biology, no batch, joint PCA (as T04).
- **Methods (each condition):** `none`, `joint`, `harmony`, `scvi`,
  `gene_rot`, all exactly as T04 (Harmony and scVI as T05a; `gene_rot` =
  `[z_A · Q_loadᵀ ; z_B]`, `Q_load = polar(W_B W_Aᵀ)` from each half's own
  PCA loadings — rigid, label-free).
- **Scores:** T04's `mix_bg`, `retention` (`f > 0`), `bio_false` (`f = 0`),
  `sil`.
- **Reproduction check:** the (`f` = 4, `σ` = 0.5, `global`) and
  (`f` = 0, `σ` = 0.5, `global`) conditions must reproduce T04's S1 and S0
  scores for `none`, `joint`, `harmony`, `gene_rot` (≤ 1e-6) and `scvi`
  (reported; same platform should match).

### Out of scope
- Operators, drift fits, scOPAlign estimators; other methods, parameters,
  seeds or replicates; tuning Harmony or scVI.

## Pre-registration

Definitions over the 24 conditions with `f > 0`:
- a method **removes batch** if `mix_bg ≥ 0.80`;
- **rigid wins** in a condition if `gene_rot` removes batch **and**
  `retention_gene_rot ≥ max(retention_harmony, retention_scvi) + 0.10`;
- **gain** = `retention_gene_rot − max(retention_harmony, retention_scvi)`.

### Gated numbers
| name | definition | computed by |
|------|-----------|-------------|
| `n_conditions` | conditions completed (must be 30) | `python reports/T04b/scripts/t04b_run.py --stage sweep` |
| `repro_t04_max_abs` | max \|score − T04\| over none, joint, harmony, gene_rot in the two T04 conditions | same |
| `repro_t04_scvi_abs` | same for scvi | same |
| `frac_rigid_removes_batch` | fraction of the 24 `f > 0` conditions where `gene_rot` removes batch | same |
| `frac_harmony_removes_batch` | same for harmony | same |
| `frac_scvi_removes_batch` | same for scvi | same |
| `frac_rigid_wins` | fraction of the 24 where rigid wins | same |
| `frac_rigid_wins_global` | same, `global` batch only (12) | same |
| `frac_rigid_wins_celltype` | same, `celltype` batch only (12) | same |
| `median_gain` | median gain over the 24 | same |
| `bio_false_max_gene_rot` | max `bio_false` of gene_rot over the 6 `f = 0` conditions | same |
| `bio_false_max_harmony` | same, harmony | same |
| `bio_false_max_scvi` | same, scvi | same |
| `t04b_outcome` | `"general"`, `"limited"` or `"none"` | `--stage report` |

### Decision rule
0. Validity: `n_conditions ≠ 30` or `repro_t04_max_abs > 1e-6` → REVISE.
1. **general** if `frac_rigid_wins ≥ 0.75` and `bio_false_max_gene_rot ≤ 0.10`.
2. **limited** if `frac_rigid_wins ≥ 0.25` (the report names the conditions
   where it wins and where it fails, e.g. strong or cell-type-specific batch).
3. Otherwise **none**.
- Expected reading (not the outcome): rigid should lose on mixing under
  `celltype` batches and at `σ = 1.0`; the question is how far its
  biology advantage reaches before that.

### What would change my mind
If the rigid correction's advantage appears only at T04's setting, it is a
single-point result and not worth taking to real data; the project would
report T04 as a case study rather than a method.

## Procedure

1. `--stage data` — build the 30 condition matrices + 6 oracles (cached;
   resumable).
2. `--stage sweep` — per condition: per-half PCA, the five methods, scores;
   `sweep.csv` (batch_type, sigma, f, method, mix_bg, retention, bio_false,
   sil). Checkpoint per condition.
3. `--stage report` — figures: `fig_retention.png` (retention vs `f`, one
   panel per batch type × `σ`, one line per method),
   `fig_mixing.png` (same for `mix_bg`), `fig_wins.png` (grid of
   win/lose/no-mix per condition); `report.json`, checksums, lockfile.

`--stage all`; detached and resumable; push `reports/T04b` to `task/T04b`
after each stage.
